## Decisões confirmadas

| ID | Decisão | Motivo/observação |
| --- | --- | --- |
| D-001 | Nome de trabalho: **Modernize** | Escolhido na conversa; marca jurídica/domínio ainda não pesquisados |
| D-002 | Tema: aplicação profissional de **IA no trabalho** | Consultoria, treinamentos e implementações são frentes imaginadas |
| D-003 | Foco geográfico inicial: **Santa Maria, RS** | Mercado de entrada desejado |
| D-004 | Visão de mercado: **diversos setores B2B** | Não limitar atuação futura a uma profissão |
| D-005 | Formato do pitch: **slides web interativos presenciais** | Não haverá vídeo gravado |
| D-006 | Tecnologia de apresentação: **HTML/CSS e JS/TS, GitHub Pages** | Preferência por Vite + TypeScript como ponto inicial, não stack imutável |
| D-007 | Desenvolvimento **documentação primeiro**, depois implementação ampla e microajustes | Evitar programar antes de fechar narrativa e requisitos |
| D-008 | Ensino incremental de empreendedorismo durante o projeto | Explicar conceitos e aplicá-los à Modernize |
| D-009 | Entrevistas com corretores **não podem ser dependência do trabalho** | Contatos existem em Florianópolis; conversas talvez ocorram |
| D-010 | **Modernização Tecnológica Contínua** é o posicionamento da empresa-mãe | A IA pode ser uma linha de produto, não todo o portfólio |
| D-011 | **Modernize IA** como produto híbrido acompanhado de treinamento | Plataforma central extensível e personalizável por cliente |
| D-012 | **Acompanhamento tecnológico contínuo** é o diferencial principal escolhido | Ainda depende de validação com compradores; não é exclusividade comprovada |
| D-013 | Usar pesquisa verificável para sustentar a tese do problema | Guardar percentuais, fontes e limitações sem fabricar validação local |
| D-014 | **Imobiliárias** como primeiro segmento do MVP | Escolha de entrada; demanda local não validada |
| D-015 | **Documentos e rotinas administrativas** como problema inicial | Limitar escopo do produto |
| D-016 | **Automação de processos administrativos** como primeiro módulo | Não apenas chatbot ou repositório |
| D-017 | **Cadastro de interessados em locação** como primeiro fluxo | Caso demonstrável com revisão humana |
| D-018 | Documentos enviados pelo interessado por **link direto, sem login** | Link é credencial; segurança adicional obrigatória |
| D-019 | Checklist inicial: **identificação, residência e renda** | Exigências adicionais fora do MVP |
| D-020 | IA faz **extração + conferência + resumo** | Sem decisão de crédito/locação pela IA |
| D-021 | Painel com **etapas, responsáveis e histórico** | Gestão operacional rastreável |
| D-022 | Dois perfis internos: **Administrador e Funcionário** | Controle de acessos |
| D-023 | Login interno exclusivamente com **Google** | Autorização da imobiliária segue obrigatória |
| D-024 | **SaaS multi-tenant** | Mesma aplicação, dados/usuários segregados entre imobiliárias |
| D-025 | **Estratégia técnica B — MVP escalável enxuto** | APIs de IA no início, abstração para outros modelos/provedores, PostgreSQL, processamento assíncrono e segregação multi-tenant; fornecedores e dimensionamento ainda não definidos |
| D-026 | **Modelo comercial: implantação + mensalidade** | Implantação cobre configuração, adaptação inicial e treinamento; mensalidade cobre plataforma, suporte e acompanhamento; personalizações maiores podem ser cobradas separadamente. Valores ainda não definidos. |
| D-027 | **Cenário financeiro-base A — Entrada acessível** | Implantação R$ 990, mensalidade R$ 299, meta hipotética de 8 novos clientes em 12 meses e custo fixo preliminar R$ 1.000/mês; parâmetros **não validados** e sujeitos a simulações de churn, CAC, impostos e custos variáveis |
